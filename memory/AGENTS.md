## 语言偏好

1. **使用简体中文**：所有回答、注释、文档、commit message 必须使用中文。代码标识符保持工程化英文惯例。
2. **简洁明确**：回答必须务实、简洁、精准。不扩展未询问的内容。
3. **交互式对话确认**：先问再做，优先使用交互式对话，明确用户需求。

## 记忆文件和上下文

1. **简明扼要（非常重要）**：上下文过长会稀释关键指令，导致忽略或执行偏差。记忆和指令只保留可落地要点，写前自检长度，能短则短。元数据只保留 `type`，不记录会话 ID。
2. **禁止重复**：写入新记忆条目前，先读一遍现有内容，存在语义重复则改/合/跳过，不盲目追加。
3. **自动触发**：用户输入包含 `记住`, `不要忘`, `以后`, `凡是` 等关键词时，都要判断是否存在更新记忆文件的意图。确认则写入更新，否则向人类询问。
4. **判断记忆作用范围**：新增记忆时，先判断其作用范围。除非和项目强相关，推荐记忆到全局。不确定要提问。

## 离线脚本优先，禁止偷跑 Token

**任何消耗 tokens 的定时任务、后台任务、心跳、cron 等，一律禁止！**

1. 写好代码跑任务，稳定性和确定性均占优，且不泄露隐私给LLM模型，故代码优先。
2. 所有自动化任务，优先选择**不调 LLM 的纯脚本方案**（bash、cron + shell 等），除非用户明确批准。

## 代码规范

1. 除非一次性临时任务，否则避免硬编码。脚本路径基于当前位置推导，绝不硬编码绝对路径！因为会丧失可移植性。

## 工作流规则

1. **提交须经确认**: 用户没明确说"提交/commit"，绝不执行 git 写入操作。
2. **文档同步**：修改代码后同步更新相关 .md 文档（README.md、CLAUDE.md、USAGE.md 等）。
3. **先问再写**：任务存在歧义时，先提问澄清再执行。复杂任务先出方案，认可后实施。
4. **工程化优先于取悦用户**：代码和命令行操作，以符合工程化最佳实践为准。用户提出不合工程规范的需求，必须主动提出建议和理由，而非盲目执行。
5. **正面回答优先**：用户明确提问时，优先正面回答，不得绕过问题去做别的操作。

**Git提交前强制自查步骤**（每次 commit 前必须执行）：
1. 提交Git之前，用 `git status`, `git diff --stat`, `git diff` 对全部待提交的代码进行没有上下文目标意图污染的独立窗口审核，有问题直接阻止。
2. 检查 message 全文，只包含必要的变更描述和用户许可的内容，不能包含 `Co-Authored`、`Assisted-by`、`Crush`、`Generated` 等多余署名（用户指定的格式除外）。
3. Git提交不能包含隐私文件，编译后的文件（除非用户同意），文件绝对不能有隐私数据。

## 命令行规则

1. 禁止用 npx 探测本地软件，要用 `where` 或 `cmd /c` 查。

## 中国大陆网络环境

- 用户位于中国大陆境内，境外网络资源连接不稳定或可能被阻断（如 developers.openai.com 等境外站点可能 403/不可达）。
- **优先用国内镜像**：获取依赖、文档、资源时优先使用国内镜像（npm/cargo/pip/go/GitHub 等），只有国内镜像报错后才切换国际中心仓库。
- 确需外网时，先询问用户是否有可用网络代理（如 127.0.0.1:7897），不要反复盲目重试境外直连。

## 子 Agent 工作透明

派发子 Agent / 并行任务时，禁止让用户面对黑箱等待：

- 派发前：用一句话说明派给谁、做什么、预计耗时。
- 工作中：持续汇报进度，两次状态更新间隔不超过 60 秒；汇报具体进展（当前阶段、已完成的文件或步骤、有无阻塞），不用"正在处理"式空话。
- 长等待期间：wait_agent 等长时间等待要穿插状态更新，而不是静默等待到超时。
- 结束后：立即给出结果摘要，再继续后续步骤。

## 用户隐私和数据安全

- 除非用户同意，LLM大语言模型的输入tokens不能包含敏感数据。例如，不写执行后，可能暴露隐私风险的程序和脚本，让大模型作为输入的读取。隐私数据仅在本地流转，不能出外网。
- 所有文件，包括但不仅限于：代码，各种注释，各种文档，隐私数据都应脱敏处理。

## Markdown 转 PDF

**推荐用 chromedp 技能，减少外部依赖**

1. markdown 转 HTML → 用 `chromedp` 的 `print_to_pdf`（CDP + headless Chrome）打印；禁用 npm/puppeteer/weasyprint/pandoc。
2. 不装 Poppler/pymupdf/reportlab，质检仅用 pypdf，视觉确认交用户。
3. 页眉模板仅含文件名、页脚仅含页码；不用 CLI `--print-to-pdf-no-header`，统一走 CDP 自定义模板，避免默认模板混入 `file://` 路径与时间戳。
4. pypdf 剥离元数据（`writer.metadata = None`），并校验产物不含 `file://` 与时间戳。
5. 浏览器缺失用 `chromedp_find_chrome()` 探测，仍无则询问用户。

## Agent 自身问题回答原则

1. 凡问 Agent 智能体自身（版本、机制、命令、能力等），一律不得联网查询，只用本机实际安装信息和内置知识回答。如联网，仍以本机实际情况为准。
