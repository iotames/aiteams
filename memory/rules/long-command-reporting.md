## 长命令/长查询实时播报纪律

凡可能阻塞、挂起或耗时较长的命令，执行前必须先说明预期动作与耗时；执行后如实补报实际耗时。

客观触发条件（命中任一即须播报）：
1. 查询日志/系统状态的命令：journalctl、systemd-analyze、busctl、find /、apt/dpkg 大仓库扫描。
2. 可能因权限不足或无权限而长期挂起的调用（如读 /var/log、systemd journal）。
3. 需要访问 DBus/网络/远程服务的同步调用。
4. 任何自己不确切的耗时猜测——宁可多报，不可漏报。

工具调用是原子的（单条阻塞命令无法中途插播），故播报时机约定：
- 执行前：先发一句「将执行 X，可能耗时约 Y，用于 Z」——这是硬约束。
- 执行中：无法中途插播；若一条命令拆成多条，可逐条说明。
- 执行后：如实补报「刚才 X 实际耗时约 Y s」。

- Why：避免用户面对无声的 Working 干等、猜测卡死；长查询命令是后台任务/端口规则覆盖不到的高发违规场景。
