# 迁移汇总报告规范（Excel，全流程单一份）

**定位**：进行中即为工作进度汇报，完成后同一结构即验收结果；不另设"验收报告"。
脚本：`scripts/gen_migration_report.py`，参数 `--user-stats / --target-stats / --baseline / --out / --batch / --note / --last-sync`。基线口径见 `SKILL.md`「基线口径」。

## 数据采集（用固化命令，不要手敲命令拼参数）

基线：`report` 子命令自动取产物目录内**最新的** `email_check_success_*.csv`（最近一次 probe 摸底结果），
不重跑 probe，并把「基线文件 / 基线数据时间」写进概要。

目标侧统计（EXO 会话内 dot-source 固化脚本，不手敲管道）：

```powershell
. <技能目录>\scripts\exo_tasks.ps1
Assert-ExoSession                     # 步骤 1：只查不断
Export-UserStats   -BatchId <批名>    # -> user_stats.csv
Export-TargetStats -BatchId <批名>    # -> target_stats.csv
```

生成报告（一条命令；需最新摸底数据时先跑 probe，再执行本命令）：

```bash
python <技能目录>/scripts/email_migration.py report --batch <批名> [--dry-run]
```

## 目标侧统计口径（硬性，含实测踩坑）

`Export-TargetStats` 已按此固化，**禁止手敲管道另搞一套口径**：

1. **邮件数 = 邮件类文件夹的 `VisibleItemsInFolder` 之和**。
   - 禁用 `Get-MailboxStatistics` 的 `ItemCount`：那是整个邮箱项数（含日历/联系人/系统项/隐藏项），实测把 3 封算成 8 封。
   - 禁用 `ItemsInFolder`：它含 `HiddenItemsInFolder`（迁移/系统写入的隐藏项，客户端看不见），实测把 3 封算成 11 项。
2. **邮件类文件夹** = `Inbox / SentItems / DeletedItems / Drafts / JunkEmail / Outbox / UserCreated`；`Calendar / Contacts / Tasks / Journal / Notes / RecoverableItems*` 等一律不计。
3. **两个实测踩坑**：
   - V3 `Get-EXOMailboxFolderStatistics` 的自建文件夹 `FolderType` 是 `User Created`（**带空格**），经典 cmdlet 是 `UserCreated`；比对前必须去掉空白，否则整片自建文件夹被漏掉（实测 emma 少算 9,903 封）。
   - 系统自动挂的 `/日历/中国 节假日` 类型也是 `UserCreated`，必须按**一级路径**排除（脚本内 `$nonMailRoots`），否则多算 174 项。
4. **`FolderSize` 是字符串**（如 `175.9 KB (180,074 bytes)`），取字节数用正则 `\(([\d,]+)\s+bytes\)`；它没有 `ToBytes()` 方法。
5. 已知口径差异（不是 bug）：占用空间取邮件类文件夹 `FolderSize`，**含隐藏项**（EXO 不提供"仅可见项"体积），小邮箱会出现"源 0.0MB → 目标 0.2MB"，在结论里说明即可。
## 表结构（只有两张表）

**Sheet1 迁移概要**（管理视角）：账号总数、已完成、同步中、失败/停止、原邮箱邮件总数、原邮箱空间合计、目标邮箱邮件总数、**目标侧口径**（写明"仅邮件类文件夹的可见邮件数"，避免被质疑把日历/隐藏项算进去）、目标邮箱空间合计、完成度（按邮件总数计）、跳过邮件合计、最近同步时间、更新时间。不放批次名等纯技术标识于正文之外。

**Sheet2 迁移数据汇总**（默认打开即激活，每账号一行），列序固定：
用户名 → 原邮箱空间占用 → 目标邮箱空间占用 → 原邮箱邮件总数 → 目标邮箱邮件总数 → 完成度（按邮件总数计）→ 最近同步时间 → 本批次已同步 → 跳过邮件数 → 迁移状态 → 说明（最右列）。

- 无源列即无法对账，禁止省略原邮箱两列；不设按空间占用计的完成度列。
- 状态文案：已完成账号显示"已完成，增量同步中"（Synced 批次在 Complete 收尾前持续每 24h 增量，如实呈现）；同步中显示"同步中"。
- 着色：完成度 <100% 标红；跳过邮件数 >0 标红。
- **说明列**（自动生成，按序判定）：完成度 >100% → "同步期间有新增邮件，故完成度超过100%"；完成度 <99% → "目标少于源 N 封，需核对是否有未迁移邮件"（N=源−目标）；跳过 >0 → "存在跳过邮件，待错误报告核对"；都不命中留空。

## 生成前置（必做）

生成报告前必须先问用户——**「是否重新联网跑 probe 对原邮箱数据摸底，还是直接使用现有的上次摸底结果文件？」** 提问时一并说明：现有基线的来源与时间点、重跑代价（约 20~30 分钟、只读源端）。**用户答复前禁止开跑，禁止自行决定**；提问前先查磁盘（产物 CSV 或 `logs/probe_*.log`），有则如实说明"可直接用现有基线"，选择权始终在用户。

## 不计入报告的内容

- 文件夹级对账（`verify` 核对报告）：属人工核对依据，单独出，不进汇总报告。
- 跳过邮件逐条明细（管理员邮箱错误报告邮件附件 CSV）：属诊断文件；报告中只在概要备注给合计与账号数。

## 规范

1. `SkippedItemCount > 0` 时在概要备注给出合计与账号数（如"跳过邮件合计 143 封，涉及 12 个账号"）。
2. 基线校准状态必须在备注写明（哪些账号为新基线、哪些为收取范围变更前旧基线待重校）。
3. 引擎预估传输量不进报告（对管理无意义）；总量与进度一律以源基线为准。
4. **输入 CSV 必须当次实时导出**：过期数据会让"最近同步时间/完成度"全部失真且无从察觉；概要"更新时间"即数据时效，与报告生成时间一致。
5. 密码与凭据字段禁止进入任何输入输出。
6. 状态用中文业务词，禁用引擎术语（Synced/Syncing 等）直接呈现。
7. **最近同步时间**：取 `Get-MigrationUserStatistics` 的 `LastSuccessfulSyncTime`（勿用 `LastSyncedDateTime`，该字段长期为空）。① 该值为 UTC，展示前转本地时区；② 为空时显示"首轮同步进行中"，禁止留空。
8. **列宽**：≥ max(表头宽, 内容宽) + 4（CJK 按 2 倍）；脚本内置 `set_widths` 自动计算，禁止写死更小值。
9. EXO 返回的时间均为 UTC，展示前转本地时区。
