# email_migrate（原始背景与实测结论）

> **本文已收敛**：全部 EXO 命令、参数与操作流程已并入 `references/migration-workflow.md`（唯一 EXO 操作手册），流程与分工以 `SKILL.md` 为准。此处只保留背景与实测结论，避免同一命令写两遍导致口径打架。

## 背景

把公司邮箱从腾讯企业邮迁移至 Microsoft 365 Exchange Online（商业标准版）：源端单邮箱无容量限制，目标端单邮箱 50GB 上限；IMAP 方案只迁邮件（收件箱 + 其他邮件文件夹），**联系人/日历/任务不迁移**，需另行方案。

## 实测结论（2026-09 现场）

1. **单封邮件大小**：官方文档"单封 35MB 上限"说法已过时。实际拦截点是目标邮箱 `MaxReceiveSize`（默认 36MB）；腾讯存量邮件实测存在超过 150MB 者，故迁移前必须把目标邮箱放大到 150MB（幂等，见 workflow 0.5「单封邮件大小限制」）。
2. **腾讯"收取范围"默认只收最近 30 天**：不改设置则 IMAP 只能看到近 30 天邮件，且无任何报错。必须逐账号改为"全部"（推荐同时勾选"收取我的文件夹"），改后重跑 probe 并与 webmail 抽样对照（收件箱 + 我的文件夹）验证生效。
3. **迁移错误查看入口**：Exchange 管理中心 → 迁移 → https://admin.cloud.microsoft/exchange#/migrationbatch （查看失败用户与跳过邮件明细）。
4. **超限处理路线**：优先官方 `-ContentFilter` 按 Received 时间裁剪（商业标准版可用，无需云归档许可）；需把旧邮件分流到主 + 云归档邮箱才用 XML mapping（要云归档许可）；imapsync 仅作细粒度筛选兜底。
