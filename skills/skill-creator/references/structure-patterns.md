# 技能章节结构模式参考

> 本文件为**低频参考**。SKILL.md 的章节结构**没有固定模板**——按任务的自然形态自由组织即可。
> 只有在对结构拿不准（不确定章节怎么组织最贴合任务）时才读取本文件。
> 以下模式是**常见起点**，不是分类法：可以混合、可以偏离，不要为了套模式而扭曲内容。

---

## 常见模式（起点，不是规定）

### 1. 工作流式（适合顺序流程）

- 有清晰的逐步流程时适用
- 例：文档技能「工作流决策树 → 读取 → 创建 → 编辑」
- 结构：# 概述 → # 工作流决策树 → # 第 1 步 → # 第 2 步……

### 2. 任务式（适合工具集合）

- 技能提供多种操作/能力时适用
- 例：PDF 技能「快速开始 → 合并 PDF → 拆分 PDF → 提取文本」
- 结构：# 概述 → # 快速开始 → # 任务分类 1 → # 任务分类 2……

### 3. 规范式（适合标准与规范）

- 适合品牌规范、编码标准、需求文档
- 例：品牌规范「品牌规范 → 颜色 → 字体 → 使用」
- 结构：# 概述 → # 规范 → # 规格 → # 用法……

### 4. 能力式（适合集成系统）

- 技能提供多个相互关联的功能时适用
- 例：产品管理「核心能力 → 编号能力列表」
- 结构：# 概述 → # 核心能力 → ### 1. 功能 → ### 2. 功能……

---

## 何时该偏离这些模式

- 任务有独特的决策结构（如多智能体编排、交互式调试会话、纯决策流程）时，直接设计贴合任务的结构
- 模式与内容冲突时，**内容优先**——结构永远服务于执行者理解，不是相反


---

## 5. 多文档技能（含 references/ + docs/ 的中大型技能）

- 适用：命令多、阶段多，SKILL.md 按渐进式加载原则必须拆分时
- 结构：# 概述 → # 文档体系与强制阅读顺序（职责矩阵表）→ # 执行模式/边界 → # 硬性纪律（高危速查 + 勘察清单）→ # 工作流阶段 → # 状态续接 → # 资源索引

设计要点：

1. **职责矩阵**：每份文档一行——定位、何时读、读哪节。执行者据此判断"下一步该读什么"，不靠猜测。
2. **高危规则必须上浮**：入口文件放速查（简短、可逐条自查），完整规范放 references 并标注主从关系。只沉底必被漏读。
3. **单一权威源**：同一规则的完整版只存在于一份文档；其他位置只放指针或压缩速查，并写明"以 X 为准"。
4. **演进即全量同步**：能力/分工变更时，用全文检索（如搜"人工""旧参数名"）找出所有过时表述，一次改齐。
5. **语态即定位**：操作手册用规范语态（必须/禁止）；需求背景、决策记录与操作内容分文档存放，不混排。
